# Validation

`useValidation()` provides ordinary Zod schema factories bound to the current Vue app and nearest
i18n provider. `createMiru()` installs the custom factory registry automatically. No Zod methods,
prototypes or global error maps are modified. No additional dependency is needed.

## Built-in factories

```ts
import { z } from 'zod';
import { useValidation, useForm } from '@rat.md/miru/composables';

const { validators } = useValidation();
const schema = z.object({
    email: validators.mailAddress(),
    productCode: validators.gtin().optional(),
    iban: validators.iban(),
    card: validators.creditCard().nullable(),
});

const form = useForm({
    schema,
    initialValues: { email: '', productCode: undefined, iban: '', card: null },
    submit: '/save',
});
```

The four built-ins return `ZodString` schemas, so optional/nullable handling, refinements, transforms,
unions and normal schema composition keep working. Inputs are validated without normalization or
coercion; add an explicit transform when the submitted representation should change. Their validation
rules match `isValidMailAddress`, `isValidGtin`, `isValidIban` and `isValidCreditCard` under support.

The schemas work anywhere a Zod schema is accepted, including the existing Miru form controller and
TanStack Form schema validators. Miru's form controller already calls `safeParseAsync`, so custom
asynchronous refinements and transformations work without a new form API.

## Localized errors

Built-in errors use `common.validation.mail_address`, `.gtin`, `.iban` and `.credit_card` through
`useI18n()`. Translations are evaluated when validation fails, rather than when the schema is created.
Changing the locale affects the next parse of an existing schema. Already-collected Zod/form errors
keep their text until the form is revalidated. Default English and German messages cover string type
errors as well as invalid strings. The host i18n adapter or custom dictionaries can override the keys.

```ts
validators.iban({ error: 'Please check your bank details.' });
validators.gtin({ error: () => hostTranslation('product.invalid_code') });
```

Only the built-in factory errors use these defaults; ordinary `z.string()` and custom schemas keep
their own Zod error configuration. Custom factories can use the context's `t`/`tc` helpers for localized
messages. Supply an error callback to evaluate the translation on each failed validation.

## Register application factories

```ts
import { createMiru } from '@rat.md/miru';
import { defineValidators } from '@rat.md/miru/plugins/validation';

export const appValidators = defineValidators({
    customerId: ({ z, t }, prefix = 'CUS-') =>
        z.string().startsWith(prefix, {
            error: () => t('validation.customer_id'),
        }),
    availableName: ({ z, t }) =>
        z.string().refine(async (value) => checkAvailability(value), {
            error: () => t('validation.name_unavailable'),
        }),
});

app.use(createMiru({ validators: appValidators }));
```

`defineValidators` preserves each factory's concrete arguments and output schema type. It does not
register factories globally or execute them. A factory receives `{ z, locale, t, tc }` followed by its
own arguments. `locale` is a readonly computed ref. The factory itself must return a Zod schema
synchronously; asynchronous work belongs inside refinements/transforms and requires async parsing.
Return boolean results from predicates rather than throwing for normal invalid input.

The registry takes a snapshot of each app's factory map at installation. Install-time `configure`
hooks can set `options.validators` or return a `validators` override before automatic registration.
Built-in names and prototype-related names are reserved. Invalid entries fail during registration,
and factories returning non-schema values fail when called.

## Type custom names in consumers

Vue injection cannot infer factory names configured in another file. Import the host map's type and
pass it as a generic when accessing app-registered names:

```ts
import type { appValidators } from '@/validation';
import { useValidation } from '@rat.md/miru/composables';

const { validators } = useValidation<typeof appValidators>();
const customer = validators.customerId('PARTNER-');
const name = validators.availableName();
```

The generic describes factories already registered by the host; it does not register anything at
runtime. For application-wide typing without a repeated generic, augment the extension interface
from a TypeScript module included by the application:

```ts
import type { appValidators } from '@/validation';
import '@rat.md/miru/plugins/validation';

declare module '@rat.md/miru/plugins/validation' {
    interface CustomValidationFactories {
        customerId: typeof appValidators.customerId;
        availableName: typeof appValidators.availableName;
    }
}
```

Then `useValidation().validators.customerId()` is typed across the application. The host remains
responsible for registering those factories in every Vue app that uses that declaration.

## Local additions and overrides

```ts
const { validators } = useValidation(
    defineValidators({
        quantity: ({ z }, minimum = 1) => z.number().int().min(minimum),
    }),
);

const quantity = validators.quantity(5);
```

Local names are inferred automatically. A local factory can override a custom app factory for this
consumer; other consumers remain unchanged. Built-ins cannot be replaced this way. Use their `error`
options or register a separately named schema when different behavior is required.

## Manual installation and SSR

```ts
import { createMiruConfig } from '@rat.md/miru/miru';
import { createMiruI18n } from '@rat.md/miru/plugins/i18n';
import { createMiruValidation } from '@rat.md/miru/plugins/validation';

app.use(createMiruConfig({ locale: 'de', validators: appValidators }));
app.use(createMiruI18n());
app.use(createMiruValidation());
```

Alternatively, pass an explicit factory map to `createMiruValidation(appValidators)`. Use
`plugins: { validation: false }` to skip automatic custom registration. Built-ins and locally supplied
factories remain usable without installing the registry. Call the composable in component setup or
`app.runWithContext`; create app instances and host-owned sources per SSR request. Schemas retain their
captured app/tree translation context when they are later parsed outside setup.

This registry is a Miru installation feature. Zod's own metadata registries remain independent.
