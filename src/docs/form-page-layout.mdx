# Form page layout

`FormPageLayout` gives a manual form its sections and responsive actions. `FormLayout` uses it internally and adds generated fields, validation display and localization. Choose one outer layout; both already render a `<form>`.

## A manual form

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { FormPageLayout, Field, FieldLabel, Input, Checkbox } from '@rat.md/miru';

const active = ref('profile');
const name = ref('Alex');
const updates = ref(true);
const saved = ref(false);
const tabs = [
    { value: 'profile', label: 'Profile' },
    { value: 'preferences', label: 'Preferences' },
];
function save() {
    saved.value = true;
} // Replace with your form controller.
function reset() {
    name.value = 'Alex';
    updates.value = true;
    saved.value = false;
}
</script>

<template>
    <FormPageLayout
        v-model="active"
        :tabs="tabs"
        primary-label="Save changes"
        secondary-label="Reset"
        navigation-label="Profile sections"
        actions-label="Profile actions"
        @submit="save"
        @secondary="reset">
        <template #header><h1>Your profile</h1></template>
        <template #default="{ tab }">
            <Field v-if="tab?.value === 'profile'">
                <FieldLabel for="manual-name">Name</FieldLabel>
                <Input id="manual-name" v-model="name" />
            </Field>
            <Checkbox v-else v-model="updates" label="Send project updates" />
            <p v-if="saved" role="status">Saved in this local demo.</p>
        </template>
    </FormPageLayout>
</template>
```

For requests and Zod validation, connect [useForm](/reference/composables/useForm). For schema-driven fields, use the [form generator](/reference/form-generator-guide).

## Desktop and mobile

The layout responds to its **available width**, so it also works inside panels. Below 1024px, tabs sit above the fields and actions dock at the bottom. From 1024px, tabs move left and actions right; side columns widen from 1280px. Inactive panels stay mounted to preserve editor state.

Desktop actions appear as primary → secondary → extra actions. Mobile keeps at most three controls: overflow → secondary → primary. Extra actions open in a bottom drawer. The layout reserves bottom space and the safe area.

## Extra actions

```vue
<FormPageLayout
    :additional-actions="[{ id: 'preview', label: 'Preview' }]"
    @action="(id) => console.log(id)"
    @submit="save">
  <!-- Your fields -->
</FormPageLayout>
```

Filter actions by permissions in your app. Bind `loading` while saving. Use `show-actions="false"` for a standalone panel.

Slots include `header`, `default` (`{ tab }`), `primary-action`, `secondary-action`, `additional-actions` and `desktop-actions`. Additional-action slots receive `close()` so you can close the mobile drawer after an action.

To add a compact app bar, render `FloatingAppBar` in `#floating-app-bar="barProps"` and bind `v-bind="barProps"`. The layout owns its docking and clearance; avoid a second fixed bar over the same footer.
