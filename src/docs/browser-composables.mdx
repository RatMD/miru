# useClient

Import from `@rat.md/miru/composables/useClient` or `@rat.md/miru`.

No plugin installation is needed. All three can be created during SSR without browser globals.
Instances belong to the calling Vue effect scope and dispose automatically when that scope ends.
Outside a Vue scope, call `dispose()` yourself. Disposal releases listeners and pending work;
it does not erase storage, unregister a worker or clear caches.

```ts
const client = useClient();
// In templates, nested refs need unwrapping; in script, read .value.
client.online.value;
client.screen.width;
client.prefersReducedMotion.value;
```

The returned readonly refs include `browser`, `browserVersion`, `browserMajorVersion`, `os`,
`osVersion`, `agent`, `cookies`, `online`, `isApple`, `isLinux`, `isWindows`, `isMobile`,
`language`, `languages`, `hasTouch`, `prefersDark`, `prefersReducedMotion`, `isStandalone`
and `isSupported`. The readonly reactive `screen` object contains viewport `width`, `height`,
`orientation` and `pixelRatio`. `refresh()` rereads browser and viewport information.

In component setup, browser reads and subscriptions start on mount. Initial width/height are zero;
orientation and online state are initially undefined. This keeps the first render consistent with SSR.
Outside component setup, initialization is immediate. Resize, connectivity, language and media-query
events update the relevant state. No test cookies are written.

Browser/OS recognition uses best-effort user-agent parsing, including Chromium Edge and desktop-mode
iPad. OS versions report the UA value (for example Windows NT), not a guaranteed marketing version.
Use feature detection for capabilities; `navigator.onLine` is not an internet availability check.
