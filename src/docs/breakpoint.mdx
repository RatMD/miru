# Breakpoint

```vue
<Breakpoint min="md" max="xl">
    <template #default="{ width, orientation }">Desktop: {{ width }} · {{ orientation }}</template>
    <template #else>Small or extra-wide viewport</template>
</Breakpoint>
<Breakpoint :min="500" :max="1100" orientation="landscape">Landscape content</Breakpoint>
<Breakpoint min="tablet" :breakpoints="{ tablet: 900 }">Custom tablet content</Breakpoint>
```

`min` is inclusive, `max` exclusive. Defaults in CSS pixels are xxs=364, xs=576, sm=640, md=768,
lg=1024, xl=1280 and xxl=1536. Import `defaultBreakpoints` to reuse this immutable map.

```ts
app.use(createMiru({ breakpoints: { md: 900, tablet: 960 } }));
```

Local `breakpoints` override app settings, which override defaults. Changing a reactive map or
threshold updates the branch. Unknown names and invalid thresholds raise RangeError.
The slots receive width, height, orientation and current; there is no extra wrapper element.

Without an explicit SSR viewport the else branch renders on the server and first client render.
Actual browser values initialize after mount, preventing hydration mismatches. Provide the same
`ssrWidth`/`ssrHeight` on both server and client when the host has an initial viewport estimate.
Orientation rules require height as well as width. Use CSS media queries when both branches should
stay mounted or responsiveness only changes presentation; switching Breakpoint branches unmounts them.
