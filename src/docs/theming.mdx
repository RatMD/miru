# Semantic colors and surfaces

Import `@rat.md/miru/style.css` before your application overrides. The theme recognizes `.dark` or `data-theme="dark"` on the document root.

## Accent

The semantic colors are `primary`, `secondary`, `accent`, `info`, `success`, `warning`, and `danger`. Accent has a complete `--ui-accent-50` to `--ui-accent-950` palette, with `--ui-accent`, `--ui-accent-foreground`, `--ui-accent-hover`, and `--ui-accent-active` aliases.

Use `variant="accent"` for Button, ButtonAction, ButtonShadow, Badge, BadgeCopy, BadgeCounter, Progress, Alert, Tooltip, Tabs, Checkbox, CheckboxGroup, RadioBox, RadioGroup, InputTags, Anchor and Code; Avatar uses `tone="accent"`. ButtonGroup composes its child button variants. DataTable action colors and FloatingAppBar tones also accept `accent`.

The compiled stylesheet includes `text-accent`, `bg-accent`, `border-accent` and `text-accent-foreground`. Palette utilities reference CSS variables, so changing the underlying tokens updates rendered components without rebuilding CSS. For a host Tailwind build, import Miru's theme mappings or map your colors to those same `--ui-*` tokens.

Colored Action and Shadow buttons use `--ui-primary-text`, `--ui-secondary-text`, `--ui-accent-text`, `--ui-info-text`, `--ui-success-text`, `--ui-warning-text`, and `--ui-danger-text` for readable ink on neutral surfaces. Their defaults use darker palette steps in light mode and lighter steps in dark mode. Live palette generators can supply contrast-adjusted values alongside the solid button colors.

## Neutral hover surfaces

`--ui-surface-hover` and `--ui-surface-hover-foreground` control neutral menu, calendar and selection hover backgrounds. These replace the earlier neutral meaning of `--ui-accent`. Migrate any old neutral accent override to these surface tokens. Accent now represents an independent semantic color.

## Live themes

Your application owns palette generation and persistence. Update the complete palette and semantic foreground/hover/active tokens on the theme root, and supply readable foreground colors for each appearance. Colored Buttons use the 900 palette step for dark surfaces, 200 for text and 600 for borders in dark mode. Hover uses an 800 surface with 100 text and a 500 border; pressing uses a 950 surface, 700 border and inset shadow. Overriding only the semantic base does not replace these palette references. Surfaces use `--ui-background`, `--ui-foreground`, `--ui-muted`, `--ui-muted-foreground`, `--ui-border` and the neutral palette. Never hard-code brand colors into a host reset for component-owned elements.
