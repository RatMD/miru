# Forms and submission

Use `useForm` for values, Zod validation and requests. Use `FormLayout` to turn field definitions into a responsive form. Your app owns the schema, endpoint and saved data.

## A complete form

Install Miru once in your app, then copy this component. Replace `/api/profile` with your endpoint.

```vue
<script setup lang="ts">
import { z } from 'zod';
import { FormLayout, defineFormSections, literal } from '@rat.md/miru';
import { useForm } from '@rat.md/miru/composables';

const { form, loading, formError, submitForm } = useForm({
    schema: z.object({
        name: z.string().trim().min(1, 'Enter your name.'),
        email: z.email('Enter a valid email address.'),
    }),
    initialValues: { name: '', email: '' },
    submit: { method: 'patch', url: '/api/profile' },
    mode: 'json',
});

const sections = defineFormSections<'name' | 'email'>([
    {
        id: 'profile',
        label: literal('Profile'),
        fields: [
            {
                type: 'input',
                name: 'name',
                label: literal('Name'),
                required: true,
                showValidation: true,
                span: 6,
            },
            {
                type: 'input',
                name: 'email',
                inputType: 'email',
                label: literal('Email'),
                required: true,
                showValidation: true,
                span: 6,
            },
        ],
    },
]);
</script>

<template>
    <FormLayout
        title="Your profile"
        :form="form"
        :sections="sections"
        :loading="loading"
        :form-error="formError"
        :save-label="literal('Save profile')"
        :actions-label="literal('Profile actions')"
        :section-selector-label="literal('Profile sections')"
        cancel-href="/profile"
        @submit="submitForm" />
</template>
```

`FormLayout` already renders a form. Do not wrap it in another `<form>`. Top-level refs such as `loading` unwrap in the template. If you keep the controller in an object, use `controller.loading.value` there.

## What happens on submit?

1. Previous errors are cleared and Zod validates the values.
2. Invalid values show field errors. No request is sent.
3. Valid values run `beforeSubmit`, then the selected transport. `loading` blocks duplicate submissions.
4. Server field errors return to the fields; a general error appears through `formError`.

The server must also validate every request. `required` adds field UI/attributes; your Zod schema defines the validation rules. `showValidation` enables optional touched/valid/error icons.

## Choose a transport

| Mode                | Use it for                                                               |
| ------------------- | ------------------------------------------------------------------------ |
| `json`              | An API request through Inertia's `useHttp` client, without a page visit. |
| `inertia` (default) | An Inertia page visit. Initialize Inertia in the host app.               |

JSON endpoints may return raw data or `{ status: 'success', result: ... }`. Error envelopes use `{ status: 'error', message?, details? }`. Use `mapErrors` for a different server format. Dot paths such as `items.0.name` normalize to `items[0].name`; `_form` holds a general error.

## Common options

```ts
// Add these to useForm({...}).
transformValues: values => ({ ...values, name: values.name.trim() }),
onSuccess: ({ result }) => console.log(result),
onError: ({ result }) => console.log(result),
```

For files, return `toFormData(values)` from `transformValues` (import it from `@rat.md/miru/support`). Call `submitForm()` for the configured target, or `onSubmit('patch', '/api/profile/1')` to override it once.

For a local preview, call `await form.validate('submit')` instead of `submitForm()`. Validation alone sends no request.
